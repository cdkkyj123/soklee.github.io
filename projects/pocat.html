Overview

포켓몬 카드 수집가들을 위한 실시간 경매 및 거래 플랫폼입니다. 경매 생성·입찰·낙찰·결제 전 과정을 Kafka 이벤트 드리븐 아키텍처로 연결해 서비스 간 느슨한 결합을 구현했습니다. Spring AI(Gemini)를 활용한 카드 이미지 분석으로 시세를 자동 추정하고, Resilience4j Circuit Breaker로 외부 API 장애 격리를 적용 중입니다. 현재 활발히 개발 진행 중인 프로젝트로, 517 commits과 14개 ADR이 누적되어 있습니다.

Tech Stack

Spring Boot Kafka Redis Elasticsearch Spring AI (Gemini) Resilience4j MySQL Docker GitHub Actions

핵심 기술 문제 · 해결

1. Kafka 이벤트 드리븐 + 트랜잭션 커밋 후 발행 순서 보장

문제: 경매 입찰·낙찰·결제 처리 시 서비스 간 강한 결합으로 장애 전파. 또한 DB 트랜잭션 커밋 전 이벤트 발행 시 데이터 불일치 위험.

기술 선택: 경매 상태 변경을 Kafka 이벤트로 발행해 서비스 간 느슨한 결합 구현. 트랜잭션 커밋 후 이벤트 발행을 보장하기 위해 Spring의 TransactionSynchronization을 활용, afterCommit 훅에서 Kafka 발행 처리.

결과: 서비스 간 결합도 감소. DB 커밋 전 이벤트 발행으로 인한 데이터 불일치 문제 제거. 입찰→낙찰→알림 이벤트 체인의 순서 보장.

2. Resilience4j Circuit Breaker — Gemini API 장애 격리

문제: Spring AI(Gemini) 카드 가격 추정 API가 외부 의존성으로, 장애 발생 시 연쇄적으로 경매 생성 기능 전체가 중단될 위험.

기술 선택: Resilience4j Circuit Breaker를 Gemini API 호출부에 적용. 장애 임계치(50% 실패 시 서킷 오픈) 설정, fallback으로 "가격 추정 불가" 기본값 반환해 경매 생성은 정상 진행.

결과: Gemini API 장애가 경매 생성 서비스로 전파되지 않아 핵심 기능 가용성 유지. 서킷 상태(오픈·클로즈드·반오픈)에 따른 자동 복구 동작 검증.

3. Redis TTL + 백업 스케줄러 이중화 — 경매 라이프사이클 관리

문제: 경매 종료 시점을 정확하게 처리해야 하나, Redis TTL 만료 알림만으로는 메시지 손실 위험. 단일 스케줄러는 서버 재시작 시 누락 가능.

기술 선택: Redis TTL + Keyspace Notification으로 경매 만료 1차 감지. 백업 스케줄러(ShedLock)를 이중화해 Redis 이벤트 손실 시에도 DB 상태 조회로 만료된 경매를 추가 처리.

결과: 경매 라이프사이클(생성→진행→종료→낙찰) 이중화로 단일 장애점 제거. 서버 재시작 후에도 누락된 경매 종료 처리 보장.
